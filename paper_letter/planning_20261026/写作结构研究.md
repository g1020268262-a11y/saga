# 代表性顶会、期刊论文的结构研究与 Letter 压缩策略

核对日期：2026-10-26。本文研究如何组织问题、贡献、分析和证据，不据此声称已经完成 SAGA 新发现的穷尽式相关工作查重。

## 1. 阅读对象与方式

## 2. 三篇论文各自提供的写作启示

**CCS 2017 的重要做法是把已证明目标与更强期待分开。** 论文 p.2 将建模、已证明性质、异常行为与规范映射分别列作贡献；p.11–12 报告双方认证状态视图的差别，并解释该行为与规范既定要求的关系。对本稿最有用的是：OTK 章节应明确发放上限仍成立，再提出领取者与使用者的一致性目标，而不先用强漏洞标题再在限制段撤回。

**IEEE S&P 2019 的重要做法是围绕精确性质解释机制与执行。** 该文先说明安全机制及具体攻击，再集中交代形式模型、适用配置与性质。对本稿可借鉴的顺序是“应满足什么 → 哪个绑定或状态环节不足 → 执行如何到达结果”；不必把短文前半部分变成验证工具教程。该文包含修复和修复后证明，而我们当前没有对应的联合修复证据，因此不能照搬这一贡献表述。

**Journal of Cryptology 2021 的重要做法是按阶段、对象和假设限定保证。** 论文用明确的阶段属性和适用模式支撑各节分析，最后再讨论设计含义。对本稿可借鉴的是：policy、OTK、ACT 的顺序固定，三项性质分别定义；不能因为使用同一协议名称，就把原生执行、Tamarin 与 TLC 的结论合成一个全系统定理。

这些是本次对所选文章的结构归纳，不是所有顶刊顶会都必须遵循的统一模板。

## 3. 贡献陈述的可迁移规则

**贡献必须让读者知道新增了哪个可核查的结论。** 建议每项只保留四个元素：研究对象、分析动作、得到的结果、成立条件；避免“提出一个先进框架”“开展大量实验”或查询总数等不能直接说明新增知识的表述。

本稿的贡献动词依次是：C1“识别并验证”、C2“建立并区分”、C3“定义并展示”。三点都回到实际执行的规则，不把更换验证工具本身当作技术增量。

**结果应紧跟支持它的证据与限制。** 主文按三项发现分章，每章内部采用相同顺序：规则／性质、机制、最小执行、验证结果、边界。这样可以在有限篇幅中减少读者跨章节查找前提的成本。

**同一个叙事不要求同一条攻击链。** 用户要求的 policy → OTK → token 是机制的执行顺序；C1 可能涉及被规范拒绝的主体，C2 主配置中的 C 则被本地策略允许，C3 以有效 token 持有者为前提。这些场景必须分别声明。

## 4. 为什么不照搬长文目录

所选长文有空间分别展开协议背景、模型语言、威胁模型、性质、攻击、证明和讨论。Letter 若照搬会形成大量半页以下章节，挤压三项结果的机制与证据。

本稿采用六节：引言、必要流程与范围、policy、OTK、ACT、讨论与结论。把模型假设放入第 2 节和对应结果段，把相关工作放入引言，把结果留在各发现所在章节。完整运行记录与源码映射进入 artifact。

这个压缩保留的是“共同问题 → 明确规则 → 具体发现 → 可核查证据 → 结论范围”的论证功能，而不是长文的标题数量。

## 5. IEICE 适配依据

**目标是现有工程对应的 IEICE Transactions on Fundamentals LETTER。** 2026-10-26 核对的 [官方作者指南](https://www.ieice.org/eng/shiori/page2_ess.html) 标注最近修订为 2026-08-25。§3.1–3.3 规定：标准 Letter 为 2 页；初投正文不含参考文献最多 4 页；Summary 约 50 词、关键词 4–5 个；官方格式不可自行改变；出版收费页数包含参考文献。

为三项结果保留基本证据空间，建议总计约 4 页，而不是强行把三点压到标准 2 页。总页数与正文上限须分别报告；最终合规仍需正文完成后用官方模板排版检查。

此次官方网页通过联网页面读取核对；本地 HTML 下载请求返回 403，因此未伪造一份“已保存的官方网页”。核对要点另存于 `sources/venue-requirements.json`。Information and Systems（D）不是本次默认目标，不能无说明地换用它的页数口径。

本轮产出章节大纲、写作研究与证据映射，保留下载来源和阅读页码。既有 `paper_letter/main.tex`、原章节、参考文献、模型与证明归档不改写；没有重跑证明器或增加实验。下一步写正文时应以审定的三点贡献及本大纲的顺序为依据。
