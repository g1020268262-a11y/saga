# Letter 的叙事、引言与贡献表达

研究日期为 2026-11-06。本报告依据 [9 篇原文的逐篇拆解](逐篇写作拆解.md)，分析作者怎样在短篇幅内建立问题、陈述贡献并组织证据。篇名、作者、原文和阅读范围可从 [研究入口](README.zh-CN.md)及[来源清单](sources-manifest.json)查阅。

## 1　引言要让读者知道哪些有关贡献的信息

本次样本的引言都在第一页给出主要结果或方案。作者先让读者知道文章增加了什么，再安排正文解释其依据。引言中可以辨认出以下五项功能，各篇按需要将它们组合在段落中。

| 功能 | 读者得到的信息 | 样本依据 |
|---|---|---|
| 确定对象 | 本文研究哪个机制、方案、模型或流程，其使用目标是什么 | L03、L05、L09 p.1 |
| 说明已有依据 | 原方案声称什么，已有分析明确了什么，前人完成到哪里 | L03、L05、L08 p.1 |
| 建立研究问题 | 哪项主张需要复核，哪种关系待澄清，哪部分范围有待扩展 | L04、L05、L08 p.1 |
| 交代本次工作 | 作者做了什么，并得到了什么结果 | 全部样本 p.1 |
| 给出意义与条件 | 结果为何影响对象的使用或设计，适用条件是什么 | L06、L07、L09 p.1 |

这些功能具有不同的压缩方式。L04用一个连续段落串联需求、相关方案、原有主张与本文结果。L07用四段逐步收窄场景。L08将基线、方法和量化结果分开写。段落安排取决于读者需要跨越多少理解步骤。

引言需要交代结果的内容与研究差异。算法细节、完整执行过程、正式定义和实验配置在主体中展开。读完引言时，读者应能说出本文的对象、被检查或改进的问题、本次结果及其意义，并能预期后文将提供哪类证据。

## 2　研究问题怎样从已有工作中生长出来

样本中可以辨认出几种建立研究问题的方式。

| 起点 | 引言的推进 | 代表样本 |
|---|---|---|
| 一项具体安全主张 | 介绍原目标与主张，说明在何种条件下出现相反结果 | L03、L04 |
| 若干模型的关系 | 简述已知关系，指出待澄清的关系，给出共同比较方法与结果 | L05 |
| 既有分析的成本 | 说明已有方法的价值及代价，给出扩展方式与实验效果 | L06 |
| 系统设计的限制 | 从使用场景说明限制，将其变成设计要求，再提出回应 | L07 |
| 已有评价的覆盖范围 | 指明基线覆盖到哪里，说明本次补充的范围和结果 | L08 |
| 角色职责与模型条件 | 交代功能职责，陈述观察，解释分析条件及设计含义 | L09 |

“此前缺少某项分析”能够说明研究尚有空间。贡献陈述还需要继续写出本次新增的结果。L05在引入共同框架后，继续给出模型关系。L08在说明分析范围后，继续给出具体结果。读者因而能够判断工作增加的知识。

本报告将这些方式归纳为写作选择，使用时需要匹配研究的真实起点与证据。原文每种研究问题都对应具体对象和分析任务。

## 3　贡献怎样表述

### 3.1　贡献句应包含可判断的结果

贡献句可以由研究对象、条件、动作、结果和意义组成。各句选择其中最影响判断的内容。

| 要表达的工作 | 可以采用的陈述方式 |
|---|---|
| 检查后发现反例 | 本文分析某机制对某性质的执行，并给出在某条件下违反该性质的执行或推导 |
| 比较后澄清关系 | 本文在共同定义下比较若干机制，并确定它们之间的具体关系 |
| 提出设计 | 本文针对某个限制提出一种方法，通过某种分析说明它满足的目标 |
| 改进验证方法 | 本文扩展既有分析步骤，并通过对照实验报告成本或覆盖范围的变化 |
| 发现更强目标存在条件 | 本文保留既有目标的定义，进一步分析某个使用场景，给出额外结论所依赖的条件 |

上述句式由本次阅读概括，方括号所代表的信息需要用真实研究内容填入。它们供起草时组织句子。

贡献句的主句承载新增结果。工具名称、配置和实验方式说明结果怎样得到。L05的贡献落在表达能力关系，L06落在相对既有方法的扩展及效果，L08落在求解得到的评价结果。选择“发现”“表明”“刻画”“提出”“验证”等动词时，应让读者能在正文找到该动词对应的证据。

### 3.2　贡献可以采用不同形式

| 形式 | 原文使用方式 | 组织时的作用 |
|---|---|---|
| 引言中的条目 | L01列出三项工作 | 便于读者预先看见几个结果之间的分工 |
| 引言中的自然段 | L03、L04、L05、L06、L07连续说明本次工作 | 保持问题、动作、结果和意义之间的连接 |
| 有局部标识的贡献段 | L09在贡献段内同时处理结果与条件 | 使主张的范围在首次出现时就可判断 |
| 结果章再次归纳 | L08在给比较结果后列出两项贡献 | 让读者把归纳结论与已经看到的证据对应起来 |

贡献第一次出现时承担预告任务。正文展开时承担论证任务。结论回收时承担归纳任务。同一结果在三个位置可以使用不同的细节层级。

### 3.3　多项结果怎样保持联系

L01的发现、方案和验证依次回应同一问题。L05的多个定理共享定义和比较准则。L08的多个评价结果共享研究对象与量度。L09的两项观察共享相关组件和一组关键推导。

共同联系可以来自同一问题的不同步骤、同一性质的不同条件、共同定义下的多个关系，或同一机制的多个执行环节。贡献段要让这种联系可见。主体可以利用共同背景、共同符号、共同结果表或连续的论证过程保持联系。

## 4　正文的叙事怎样展开

### 4.1　问题驱动的安全分析

L03从原有主张进入原协议，再给关键推导和影响。L04在核心分析中先写直观观察与小例子，再给一般步骤和成本。L01详细说明问题后继续进入方案及其验证。作者根据需要解释的结果，决定在哪里增加细节。

这类文章的核心分析段通常包含一个可以检查的判断、使判断成立的条件、关键执行或推导，以及它对原目标的影响。图表承担流程或例子的解释，文字负责连接步骤和结论。

### 4.2　共同定义支撑多个形式化结果

L05先统一定义和语义，再介绍比较准则，接着给定理、反例图和证明要点。综合结果图在后面汇总新旧关系。各个结果因前文的共同表示而能够直接比较。

该类叙事需要先让读者理解被比较的对象、比较标准与命题含义。证明细节按支撑结论所需的程度进入主文，进一步依据提供明确的查阅位置。

### 4.3　要求驱动的设计与分析

L02先列安全要求，再介绍设计和形式化推导，最后对照要求进行讨论。L07先在问题章给设计规则，再用方案步骤回应规则，随后说明攻击者目标、假设和分析理由。

要求或规则在这里承担章节之间的连接。读者可以据此判断每个设计选择和分析段落为何出现，以及它回应前文哪个问题。

### 4.4　方法与效果逐步展开

L06先交代已有分析过程和实际例子，再引出成本问题。新增方法依次通过小例子、转换方式、实际应用和对比结果展开。L08先给定义、编码与对象，再给方法步骤和结果比较。

这类文章先让读者理解方法作用于什么、依据什么量比较，再呈现效果。方法机制与评价证据在相邻章节中互相支撑。

## 5　各部分具体写什么

| 部分 | 可以承担的写作任务 | 原文中的位置 |
|---|---|---|
| 摘要 | 交代对象、问题、本次动作和主要结果，概括适用范围或代价 | L01、L06、L08、L09摘要 |
| 引言 | 定位工作、建立问题、预告贡献及其意义 | 全部样本§1 |
| 必要背景 | 解释后文使用的参与方、操作、状态、规则或算法组件 | L01§2、L03§2、L09§2 |
| 性质与假设 | 说明判断标准、对象表示以及结论依赖的条件 | L02§2.1与§3、L05§2—3、L07§4 |
| 核心分析 | 给命题、关键执行、推导或方法步骤，解释结果如何成立 | L03§3、L04§3、L05§3、L06§5 |
| 结果与比较 | 按同一对象和量度比较结果，并解读差异 | L02§4、L06§5.3、L08§5 |
| 讨论与范围 | 说明结果适用的条件、影响对象和设计含义 | L03§3、L06§6、L09§1与§3 |
| 结论 | 回答开头提出的问题，归纳完成的结果，按需要指出后续方向 | 各篇最后一章 |

各项任务在实际文章中有不同组合。L01把形式化内容放在方案分析小节。L02和L05给形式化内容较大空间。L07把精确问题陈述与设计规则放在同一章。章节安排应让下一步论证所需的信息已经出现。

章节开头可以直接提出本章处理的判断或任务。中间提供对象、过程和证据。结尾解释所得结果与本章任务之间的关系。L03第三章开头重新对准原有主张，结束时说明影响范围及修改方向。L06第五章先交代前一步的限制，再逐步解释改进，最后以实际效果回应这个限制。

## 6　篇幅、节奏和图表

本次样本有 4—6 个主章节，主要结果或方案都在第一页引言出现。正文展开的长短取决于读者判断该结果需要多少信息。L03、L04的最后一页主要为文后材料，L02的第五页主要为附录。比较篇幅时，可以同时记录主文结束位置和全文页数。

| 图表形式 | 它减少的阅读负担 | 样本 |
|---|---|---|
| 正常流程、问题流程、改进流程 | 让读者直接定位操作与变化 | L01 图1—3 |
| 要求比较表 | 让读者回看各方案对应的评价目标 | L02 表3 |
| 小例子 | 在一般过程之前解释关键现象 | L04 表1、L06 图3 |
| 多个反例图与综合关系图 | 帮助读者理解各命题及其共同结果 | L05 图1—6 |
| 基线和本次结果共用的表格 | 保持比较对象与量度一致 | L08 表2—4 |

一般背景与相关工作按论证任务选取。L04的引言高度集中于两代方案和待检验主张。L05需要较多模型背景来建立比较对象。L08在对象章保留已有结果小节，为后面的比较表提供基线。作者在这些位置安排信息，是为了让核心判断能够被理解和检查。

结果表之后仍需要文字说明关键差异及其意义。形式化结果、执行见证、实现观察和性能数据各自回答不同的问题，段落应说明该证据支撑的主张。

## 7　后续编排时可复用的工作表

为每项既定贡献填写下表，可以确定引言要预告什么，以及主体需要哪些信息。它供后续讨论章节安排时使用。

| 项目 | 应记录的内容 |
|---|---|
| 分析对象 | 机制、流程或模型中的具体对象 |
| 已有保证或预期目标 | 规范、实现或本次研究明确提出的要求 |
| 研究问题 | 本次要确定的关系或执行行为 |
| 分析条件 | 参与方能力、运行条件、模型或实现范围 |
| 新结果 | 可由证据判断的发现、命题或设计结论 |
| 核心依据 | 推导、执行、形式化结果或对比数据 |
| 解释意义 | 该结果怎样影响对机制的理解或使用 |
| 章节依赖 | 读到核心分析前需要知道的信息 |
| 收束位置 | 引言中的预告如何在结果和结论中被回收 |

对具有多个结果的稿件，还需确定它们共享的问题、对象或判断标准。共同内容可以集中交代，各项分析再处理自身条件和证据。后续为 SAGA 编排时，可依据这些任务和依赖安排 policy、OTK、ACT/token 三项既定结果。

## 8　研究范围

本次选择9组不同作者的IEICE A、D刊Letter，兼顾协议安全、形式化比较、验证方法、系统设计和求解器分析。35页均已提取文字并检查渲染，重点阅读摘要、引言、章节连接、贡献陈述及结果回收。归纳属于这一目的性样本，代表可观察的组织选择。原文的证明与实验作为作者论证的组成部分阅读，记录中将其标注为文献报告结果。
