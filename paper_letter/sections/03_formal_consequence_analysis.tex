\section{Formal Consequence Analysis}
\label{sec:formalization}
\label{sec:attack-path}

\paragraph{Decision input.}
\label{sec:implementation-mapping}
The symbolic model fixes the recorded divergence: the specification denies and
the observed implementation permits. ProVerif assumes these facts; it does not
run Python or the production matcher, discover the inconsistency, or establish
implementation refinement.

\paragraph{Model assumptions.}
The valid registered initiator follows the prescribed symbolic peer process and
cannot alter the receiver's fixed policy; reachability is not an
arbitrary-adversary reachability claim. The Provider and Certificate Authority
(CA) are trusted, cryptographic checks are effective, and private keys remain
uncompromised; a private symbolic channel abstracts authenticated, confidential
transport.

In the symbolic receiver, \texttt{TokenIssue}$(R,I,t)$ occurs after
\texttt{ActiveToken} stores receiver $R$, initiator $I$, encrypted token $t$,
and $I$'s public access-control key, before $t$ is sent. For private-channel
message $m$, \texttt{ChatAccept}$(R,I,t,m)$ occurs only after checking the fixed
identity and an \texttt{ActiveToken} entry matching receiver~$R$,
initiator~$I$, presented token~$t$, and $I$'s sender public key.

\paragraph{Queries and results.}
The archived ProVerif 2.05 run (\texttt{proofs/}\allowbreak\texttt{evidence},
22 September 2026) reports \texttt{ChatAccept} reachable under the fixed
divergence. Separately, it reports this non-injective correspondence as true:
\[
 \mathsf{ChatAccept}(R,I,t,m)
 \Longrightarrow \mathsf{TokenIssue}(R,I,t)
\]
It requires prior \texttt{TokenIssue} for the same receiver $R$, initiator $I$,
and encrypted token $t$ used by \texttt{ChatAccept}; this establishes token-origin
consistency, not intended policy permission. Under the fixed divergence, it
coexists with specification denial. Issuance appears in the \texttt{ChatAccept}
witness; no standalone \texttt{TokenIssue} reachability query exists.

The empirical and symbolic executions are compared only at the level of
authorization decisions and token-lifecycle events; no object-level refinement
is established. Only the symbolic execution reaches message acceptance.
