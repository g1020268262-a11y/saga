\section{Formal Consequence Analysis}
\label{sec:formalization}
\label{sec:attack-path}

\paragraph{Decision input.}
\label{sec:implementation-mapping}
The formal model is instantiated with the recorded divergence:
the specification denies the request, while the observed implementation
permits it.
The decision bridge reconstructs the fixed symbolic scenario from checked
evidence. ProVerif consumes fixed divergence facts; it does not execute Python
or the matcher, discover the inconsistency, or prove refinement.

\paragraph{Model assumptions.}
The initiator has a valid registered identity, follows the prescribed symbolic
peer process, and cannot alter the receiver's fixed policy; reachability is
not an arbitrary-adversary reachability claim. The Provider, CA, effective
cryptographic checks, and honest private keys are trusted. A private symbolic
channel abstracts authenticated, confidential transport, with symbolic state
for handoff, token issuance, and message acceptance.

\paragraph{Queries and results.}
The run reports \texttt{ChatAccept} reachable under the fixed divergence.
Separately, ProVerif reports the following non-injective correspondence as true:
\[
 \mathsf{ChatAccept}(R,I,t,m)
 \Longrightarrow \mathsf{TokenIssue}(R,I,t)
\]
It requires prior issuance for the same participants and token, not
intended policy permission. Issuance appears in the acceptance witness; no
standalone \texttt{TokenIssue} reachability query exists.

The formal execution and consumer validation are separate experiments:
the former reaches symbolic message acceptance, while the latter stops at
token issuance and storage.
