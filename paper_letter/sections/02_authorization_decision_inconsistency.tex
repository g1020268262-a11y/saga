\section{Authorization Decision Inconsistency}
\label{sec:authorization-inconsistency}

\paragraph{Workflow and policy semantics.}
An initiating agent requests contact with a receiving agent through SAGA's
Provider. The receiving user's ordered contact rulebook associates identity
patterns with integer budgets. Both the Provider and receiver invoke the
shared matcher against the initiating identity. The Provider checks the
result before releasing contact material, and the receiver checks its local
policy before issuing a token.

For a fixed rulebook $P_R$ and valid initiating identity $I$, the documented
contract selects the most specific matching rule, using
\texttt{aid\_specificity()}. For the unique highest-scoring match with
budget $b^*$, the specification decision used here is
\[
  \mathsf{Allow}_{\mathrm{spec}}(P_R,I)
  \Longleftrightarrow b^*>0.
\]
The Provider's \texttt{/access} check treats only positive budgets as
permission. Equal-score conflicts, changing policies, and zero budgets are
outside the evaluated cases.

\paragraph{Root cause and observation.}
In the inspected matcher, \texttt{best\_pattern} is initialized to
\texttt{None} but never updated when a matching rule changes the returned
budget. Later rules are therefore compared with the initial sentinel rather
than the best previous match, making the last matching rule determine the
result. Direct calls to the unmodified production matcher use a specific
pattern with budget $-1$ and specificity $70$, and wildcard \texttt{*} with
budget $10$ and specificity $0$.

An independent finite specification evaluator selects the specific denial
for both orders. Writing
\[
  \mathsf{Allow}_{\mathrm{impl}}(P_R,I)
  \Longleftrightarrow \mathtt{match}(P_R,I)>0,
\]
the specific-deny/wildcard-allow order yields
$\mathsf{Allow}_{\mathrm{impl}}\neq\mathsf{Allow}_{\mathrm{spec}}$.
The reverse order returns the specified denial, establishing order dependence.
Table~\ref{tab:matcher-evaluation} describes rule order; the D/A label in
Section~\ref{sec:consumer-propagation} instead denotes specification and
implementation decisions.
