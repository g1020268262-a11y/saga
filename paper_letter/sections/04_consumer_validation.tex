\section{Consumer-Side Propagation Validation}
\label{sec:consumer-propagation}
\label{sec:evaluation}

Archived source hashes bind the matcher, Provider, receiver, and token-related
cryptographic code to the pinned upstream baseline. The harness drives the
production \texttt{/access} route and receiver handler using signed
registration material, local certificates, and in-memory transport, retaining
production cryptographic checks. Both consumers call the original matcher;
wrappers record and return its result unchanged. Fixtures preset neither
authorization decisions nor token state.

\paragraph{Cases and controls.}
Both consumers use identical policies. D/A places specific deny ($-1$) before
wildcard allow ($10$); A/A makes both budgets $10$, and D/D reverses the D/A
order. The letters denote specification and observed implementation decisions,
respectively. Each case ran once with fresh state and one OTK. A/A reaches
token sending and storage; D/D returns HTTP~403 without OTK release or state
change and never reaches the receiver, so receiver rejection remains untested.
