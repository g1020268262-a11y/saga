## 结果应如何解释

OTK 的一次性消费、token 对实际发送方 PAC 的绑定以及 Provider 的发放计数，可以同时成立，但不自动建立领取者与使用者的一致性。本结果没有证明 Provider 多发了 OTK；它区分了发放上限与跨身份实际使用上限。

两个候选性质是本次明确提出的检查目标；不据此声称原论文已经承诺或证明在主动转交／协作发送方条件下，这两个更强目标成立。

这是固定配置的符号模型分析，没有原生网络重放，没有完整注册、策略更新、撤销、任意预算、token 多次使用或线程竞态验证。

禁止转交对照中 B、C 均正常可达，相关候选性质成立；明确拒绝 C 的对照中C 本来就不可达，因此该对照中针对 C 的安全性不能单独作为非空证明。
