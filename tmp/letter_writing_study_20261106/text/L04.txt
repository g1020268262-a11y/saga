Security Analysis of Yeh-Tsai Security Mechanism*
Dae Hyun YUMa), Jong Hoon SHIN, Nonmembers , and Pil Joong LEE, Member
SUMMARY Yeh and Tsai recently proposed an enhanced mobile com
merce security mechanism. They modified the lightweight security mech
anism due to Lam, Chung, Gu, and Sun to relieve the burden of mobi
clients. However, this article shows that a malicious WAP gateway can 
successfully obtain the mobile client's PIN by sending a fake public key of 
a mobile commerce server and exploiting information leakage caused by 
addition operation. We also present a countermeasure against the propos
attack.
key words: security analysis, security protocol, mobile commerce, WA
authentication
1. Introduction
As mobile devices become popular, electronic transactions 
over the mobile platform grow fast. To accelerate this trend, 
end-to-end security between the mobile client and the mo-
bile commerce server should be guaranteed. Lam et al. 
proposed a lightweight security mechanism for protecting 
mobile transactions, which was designed to meet the secu-
rity needs in face of the resource constraints [1]. However, 
the lightweight mechanism depends on the assumption that 
the mobile client should have the mobile commerce server's 
public key in advance. To remove this drawback and gain 
more efficiency, Yeh and Tsai proposed an enhanced mobile 
commerce security mechanism [2]. The main idea was to 
utilize the WAP gateway instead of the mobile client to ver-
ify the mobile commerce server's public key. The authors 
claimed that their mechanism ensures that even a malicious 
WAP gateway cannot get the mobile client's PIN by sending 
a faking public key. However, we show that their security 
mechanism can be broken by a malicious WAP gateway by 
amplifying information leakage in addition operation. We 
also present a countermeasure against the proposed attack.

Even though the Yeh-Tsai security mechanism uses a ran-

show that the use of Ra+1 in the Step 2 allows a mali-
cious WAP gateway to get a subtle advantage in attacking 
the password PIN. We will utilize the following two ob-
servations. First, if the malicious WAP gateway sends a

5. Conclusion
We showed that the Yeh-Tsai security mechanism is not se-
cure against malicious WAP gateways; the addition opera-
tion leaks a partial information on the random number Ra 
(and thus the secret password PIN). A simple countermea-
sure against the proposed attack is to use a cryptographic 
hash function instead of the addition operation, which does 
not reveal any information on PIN. While this countermea-
sure thwarts the proposed attack, it does not guarantee the 
security against other attacks. Therefore, we recommend 
that security engineers should design protocols based on 
the provable security methodology (e.g., see [5]) to protect 
against all possible attacks.
